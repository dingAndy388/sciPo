================================================================================
  一、通用结构与约定
================================================================================

[时间口径]  —— 最重要的一条：所有时长一律填「游戏日」
  日历：30 日 = 1 月；12 月 = 1 年 = 360 日；第 0 日显示为 0年1月1日。
  单位：`Duration` / `GrowInterval` / `PopulationGrowthInterval` 等的单位都是**日**，
        填 30 就是"30 个游戏日（1 个月）"，不是秒。
  节拍：任务按日推进，每过一个游戏日结算一次（一帧跨多日会逐日补算，不会漏结算）。
        固化的短节拍已集中定义在 `Scripts/Core/Time/TimeConstants.cs`：
          事件掷骰       1 日/次   （EventRollDays）
          单位攻击结算   1 日/次   （UnitAttackDays）
          单位移动/MP    10 日/次  （UnitMoveDays）
          经济结算       30 日/次  （ResourceSettlementDays = 月结）
  流速（只影响"真实时间→游戏日"的换算，不影响配置）：三档 1 / 3 / 6 日每真实秒 + 暂停。
  取值范围（设计稿 A4 行）：建造 30~300 日、研究 0~180 日、事件 5~30 日、
        人口增长 180~300 日、经济 30 日。
  自检：任何时长字段 > 360（1 年）都会被启动期校验判为 warning「疑似仍是秒口径」
        —— 见附录C。

[Modifier 格式]
  所有系统共享的 Modifier 结构，用于表示加成/减益效果。

  字段:
    Target  (string) - 效果目标名称，如 "GoldGrowth", "Attack", "Movement"
    Type    (string) - "Percent" 或 "Absolute"
    Value   (float)  - 效果数值

  示例:
    { "Target": "GoldGrowth", "Type": "Percent", "Value": 0.2 }
    → GoldGrowth 提升 20%

    { "Target": "Attack",     "Type": "Absolute", "Value": 5 }
    → 攻击力 +5

[TechRequirements 格式]
  Dictionary<string, List<string>> — 键=科技树ID, 值=需要已研究的科技节点ID列表

  示例: { "physics": ["friction", "field"] }
  → 必须已研究 physics 树下的 "friction" 和 "field" 节点

[ResourceCost 格式]
  Dictionary<string, float> — 键=资源名, 值=消耗数量

  示例: { "Gold": 100, "Wood": 50 }
  → 消耗 100 金币 + 50 木材

[DependentModifiers 格式]
  List<string> — 直接填写 modifier target 名称，系统会在增长时用 ModifierManager
  以这些 target 查找所有注册的 modifier 并加总到 BaseGrowth 上。

  示例: ["GoldGrowth"]
  → 游戏内任何来源注册了 GoldGrowth modifier 都会被累加到金币增长率

================================================================================
  二、资源池配置 (Resources)
================================================================================

  文件名建议: Config/Resources.json
  根元素: { "Resources": [ ... ] }

  [字段说明]

  字段名             类型     必填  说明
  ────────────────  ────────  ────  ─────────────────────────────────
  Name              string    是    资源唯一标识，如 "Gold", "Wood", "Food"
                                    也用作资源消耗时的 key
  Description       string    否    资源描述文本
  GrowInterval      int       是    自然增长/结算间隔（**游戏日**）。系统每隔这么多天
                                    结算一次并按 DependentModifiers 汇总产出。
                                    填 30 = 月结（推荐值）；填 0 表示不自动结算
  BaseGrowth        float     是    每次结算的基础数值。最终结算量 =
                                    ModifierManager(DependentModifiers, BaseGrowth)
                                    填 0 表示"基础产出为 0，全靠建筑/科技/事件的 Modifier"
  BaseValue         float     是    初始资源量（新游戏开局时）
  BaseLimit         float     是    资源上限，增长到此值后停止
  DependentModifiers [string]  否   修饰器目标名列表。留空写 [] 即可

  [完整样板 JSON]
  ```json
  {
    "Resources": [
      {
        "Name": "Gold",
        "Description": "金币，用于建造和研发",
        "GrowInterval": 30,
        "BaseGrowth": 1.0,
        "BaseValue": 0,
        "BaseLimit": 999999,
        "DependentModifiers": ["GoldGrowth"]
      },
      {
        "Name": "Wood",
        "Description": "木材，用于建造",
        "GrowInterval": 30,
        "BaseGrowth": 0.5,
        "BaseValue": 0,
        "BaseLimit": 500,
        "DependentModifiers": ["WoodGrowth"]
      },
      {
        "Name": "Idea",
        "Description": "科技点，用于研发",
        "GrowInterval": 30,
        "BaseGrowth": 0,
        "BaseValue": 0,
        "BaseLimit": 999999,
        "DependentModifiers": ["IdeaGrowth"]
      }
    ]
  }
  ```

  [注意事项]
  - GrowInterval 一律填 30（月结）：设计稿的经济节拍就是"每月结算一次"。
  - "Idea" 的 BaseGrowth 填 0 + GrowInterval 填 30：基础产出为 0，但**照样按月结算**，
    以便把建筑的 `IdeaGrowth` Modifier（如 School 250/月）结算进池子。
  - 资源名区分大小写，必须与建筑/单位配置中的 ResourceCost key 一致
  - DependentModifiers 填的是 modifier 的 Target 名，不是资源名

================================================================================
  三、建筑配置 (Buildings)
================================================================================

  文件名建议: Config/Buildings.json
  根元素: { "Buildings": { "building_id": {...}, ... } }

  [字段说明]

  字段名                 类型                    必填  说明
  ────────────────────  ──────────────────────  ────  ───────────────────────
  BuildingId            string                   是    建筑唯一标识(与 key 同)
  Name                  string                   是    显示名
  ResourceCost          { string: float }        是    建造消耗资源
  TerrainRequirements   [string]                 是    可建造地形列表(地形ID)
  TechRequirements       { string: [string] }    否    建造所需科技前提
  Modifiers             [Modifier]              否    建成后注册的全局效果
  Duration              float                    是    建造耗时(**游戏日**)
  Actions               [string]                 是    建筑可执行动作列表
                                                      当前支持: "CanResearch"
  VisionRadius          int                      否    开迷雾半径(格),默认填0
  IsHousing             bool                     是    是否为住房(true/false)
  PopulationRadius      int                      否    住房辐射人口半径(格)
  PopulationCap         int                      否    住房提供人口上限(**半径内总计**)
  PopulationGrowthInterval int                   否    人口增长间隔(**游戏日**, 300 = 设计稿的营地 lv.I)
  TrainableUnits        [string]                 否    可训练单位 Id 列表(空 = 不能训练;
                                                      设计稿: 工坊→worker, 军营→swordsman/archer)
  TrainingQueueLimit    int                      否    训练队列上限(默认 5; 0 = 不排队;
                                                      同时只训练 1 个是引擎口径, 不需要填)

  [完整样板 JSON]
  ```json
  {
    "Buildings": {
      "camp": {
        "BuildingId": "camp",
        "Name": "营地",
        "ResourceCost": { "Wood": 20 },
        "TerrainRequirements": ["plain"],
        "TechRequirements": {},
        "Modifiers": [],
        "Duration": 90,
        "Actions": [],
        "VisionRadius": 1,
        "IsHousing": true,
        "PopulationRadius": 1,
        "PopulationCap": 9,
        "PopulationGrowthInterval": 300,
        "TrainableUnits": [],
        "TrainingQueueLimit": 0
      },
      "workshop": {
        "BuildingId": "workshop",
        "Name": "工坊",
        "ResourceCost": { "Wood": 30 },
        "TerrainRequirements": ["plain"],
        "TechRequirements": {},
        "Modifiers": [],
        "Duration": 90,
        "Actions": ["CanTrain"],
        "VisionRadius": 2,
        "IsHousing": false,
        "PopulationRadius": 0,
        "PopulationCap": 0,
        "PopulationGrowthInterval": 0,
        "TrainableUnits": ["worker"],
        "TrainingQueueLimit": 5
      },
      "school": {
        "BuildingId": "school",
        "Name": "学院",
        "ResourceCost": { "Gold": 100, "Wood": 50 },
        "TerrainRequirements": ["plain"],
        "TechRequirements": {},
        "Modifiers": [
          { "Target": "IdeaGrowth", "Type": "Absolute", "Value": 250 }
        ],
        "Duration": 240,
        "Actions": ["CanResearch"],
        "VisionRadius": 3,
        "IsHousing": false,
        "PopulationRadius": 0,
        "PopulationCap": 0,
        "PopulationGrowthInterval": 0,
        "TrainableUnits": [],
        "TrainingQueueLimit": 0
      },
      "military_camp": {
        "BuildingId": "military_camp",
        "Name": "军营",
        "ResourceCost": { "Gold": 80, "Wood": 40 },
        "TerrainRequirements": ["plain"],
        "TechRequirements": {},
        "Modifiers": [],
        "Duration": 60,
        "Actions": ["CanTrain"],
        "VisionRadius": 3,
        "IsHousing": false,
        "PopulationRadius": 0,
        "PopulationCap": 0,
        "PopulationGrowthInterval": 0,
        "TrainableUnits": ["swordsman", "archer"],
        "TrainingQueueLimit": 5
      }
    }
  }
  ```

  [注意事项]
  - 非住房建筑: IsHousing=false, PopulationRadius=0, PopulationCap=0,
    PopulationGrowthInterval=0
  - 训练口径（v0.3 / WP-2.5）：所有单位**由建筑训练**（设计稿），因此每个单位至少要出现在
    某个建筑的 TrainableUnits 里（校验器对"没有任何建筑可训练它"记 warning）；
    训练建筑的 Actions 需含 CanTrain（与 TrainableUnits 不匹配会被校验器提示）
  - 训练队列：TrainingQueueLimit 个排队名额（默认 5），**同时只训练 1 个**（引擎口径）；
    入队时扣资源、完成时扣人口（PopulationCost）并在建筑格或相邻空格落位
  - TrainingQueueLimit=0 表示"该建筑不训练"（与 TrainableUnits=[] 一起用于营地/学院这类非训练建筑）
  - 建筑 Id 采用设计稿口径（v0.3 / WP-2.7）：营地 camp / 工坊 workshop /
    学院 school / 军营 military_camp（旧原型 house、library、barracks 已废弃）
  - Duration 单位是游戏日；设计稿 A4 给的建造区间是 30~300 日
    （示例：营地 90 / 工坊 90 / 学院 240 / 军营 60，均取自设计稿"建造时间"列）
  - 住房人口三件套取自设计稿"效果"列（营地：上限 9、半径 1 格、增长间隔 300 秒 → 300 日）
  - 人口上限口径（v0.3 / WP-2.3）：`PopulationCap` 是**半径 `PopulationRadius` 内的人口总计**
    （设计稿原文"半径 1 格内总计 9 人"），不是每格配额 —— 半径 1 的 7 格共享这 9 个名额；
    增长落在住房所在格。人口增长还会经过 `PopulationGrowth` 修正器
    （`{Target:"PopulationGrowth", Type:"Absolute"|"Percent"}`，基数 1 人/间隔）
  - 产出用 Modifiers: { "Target": "IdeaGrowth", "Type": "Absolute", "Value": 250 }
    → 每次月结（Resources.GrowInterval=30）把 250 计入 Idea 的产出基数
  - Actions 当前只支持 "CanResearch"，留空写 []
  - TechRequirements 格式: { "科技树ID": ["节点ID1", "节点ID2"] }
  - VisionRadius=0 表示建筑不提供视野

================================================================================
  四、单位配置 (Units)
================================================================================

  文件名建议: Config/Units.json
  根元素: { "Units": { "unit_id": {...}, ... } }

  [字段说明]

  字段名                 类型                    必填  说明
  ────────────────────  ──────────────────────  ────  ───────────────────────
  UnitId                string                   是    单位唯一标识(与key同)
  ResourceCost          { string: float }        是    训练消耗资源
  TerrainRequirements   [string]                 是    可训练地形列表
  TechRequirements       { string: [string] }    否    训练所需科技前提
  Duration              float                    是    训练耗时(**游戏日**)
  HP                    float                    是    生命值
  Attack                int                      否    攻击力(废弃,用下面)
  Movement              int                      否    移动力(废弃)
  Actions               [string]                 是    可执行动作:
                                                      "CanBuild"/"CanMove"/"CanAttack"
  VisionRadius          int                      否    视野半径(格),默认3
  MoveRechargePerTick   float                    是    每 10 **游戏日**恢复的MP(移动点)
  AttackRadius          int                      是    攻击半径(格),0=近战
  AttackDamage          float                    是    每次攻击结算造成的伤害(每 1 **游戏日**结算一次)
  PopulationCost        int                      是    训练消耗的人口

  [完整样板 JSON]
  ```json
  {
    "Units": {
      "worker": {
        "UnitId": "worker",
        "ResourceCost": { "Gold": 20 },
        "TerrainRequirements": ["plain"],
        "TechRequirements": {},
        "Duration": 30,
        "HP": 50,
        "Attack": 0,
        "Movement": 5,
        "Actions": ["CanBuild", "CanMove"],
        "VisionRadius": 3,
        "MoveRechargePerTick": 3,
        "AttackRadius": 0,
        "AttackDamage": 0,
        "PopulationCost": 1
      },
      "swordsman": {
        "UnitId": "swordsman",
        "ResourceCost": { "Gold": 50, "Wood": 20 },
        "TerrainRequirements": ["plain"],
        "TechRequirements": {},
        "Duration": 35,
        "HP": 100,
        "Attack": 8,
        "Movement": 4,
        "Actions": ["CanMove", "CanAttack"],
        "VisionRadius": 4,
        "MoveRechargePerTick": 2,
        "AttackRadius": 0,
        "AttackDamage": 8,
        "PopulationCost": 1
      },
      "archer": {
        "UnitId": "archer",
        "ResourceCost": { "Gold": 60, "Wood": 30 },
        "TerrainRequirements": ["plain"],
        "TechRequirements": {},
        "Duration": 50,
        "HP": 60,
        "Attack": 6,
        "Movement": 3,
        "Actions": ["CanMove", "CanAttack"],
        "VisionRadius": 5,
        "MoveRechargePerTick": 1.5,
        "AttackRadius": 3,
        "AttackDamage": 6,
        "PopulationCost": 1
      }
    }
  }
  ```

  [注意事项]
  - AttackRadius=0 表示近战单位，必须移动到目标同一格才能攻击
  - AttackRadius>0 表示远程单位，可以隔格攻击
  - MoveRechargePerTick 是每 10 游戏日恢复的 MP，移动一格消耗
    地形MoveCost（设计示例：移动力 10 的单位跨消耗 5 的平原有余，
    跨消耗 25 的山地需等 30 日）
  - AttackDamage 按游戏日结算：每 1 日造成一次伤害（持续战斗）
  - Duration 单位是游戏日（设计示例：工人 30 日 / 民兵 35 日 / 弓箭手 50 日）
  - 单位需要先拥有 "CanBuild" action 才能调用建造动作建造建筑
  - 单位训练完毕后会自动注册 Move engine (IntervalTask)

================================================================================
  五、科技树配置 (TechTrees)
================================================================================

  文件名建议: Config/TechTrees.json
  根元素: { "TechTrees": { "tree_id": {...}, ... } }

  [字段说明]

  字段名             类型                    必填  说明
  ────────────────  ──────────────────────  ────  ───────────────────────
  (树根 key)        string                   是    科技树ID, 如 "military"
  ────── 每个科技树节点下 ──────
  Techs             { string: {...} }        是    该树所有科技节点
    ──── 每个科技节点 ────
    Id              string                   是    节点ID(与key同)
    Prerequisites   [前置]                   否    前置科技列表，三种写法等价（见下）
    Cost            float                    是    研发消耗的"Idea"资源量
    Duration        float                    是    研发耗时(**游戏日**，设计区间 0~180 日)
    Modifiers       [Modifier]              否    研发完成后注册的效果

  [Prerequisites 三种写法]（v0.3 / WP-2.1 起支持跨树）
    ① 本树节点（旧表写法，继续有效）: "mathematics"
    ② 跨树·紧凑写法               : "science:counting"      ← 冒号前是树 Id
    ③ 跨树·结构体写法             : { "TreeId": "science", "NodeId": "counting" }
    三者等价；推荐跨树时用 ②（最短、也最不容易写错）。
    校验：跨树前置的**树 Id 与节点 Id 都必须真实存在**，否则判 error ——
          填错就等于"该科技永久不可解锁"（TECH-07 的成因）。

  [完整样板 JSON]
  ```json
  {
    "TechTrees": {
      "military": {
        "Techs": {
          "melee_weapons": {
            "Id": "melee_weapons",
            "Prerequisites": [],
            "Cost": 50,
            "Duration": 20,
            "Modifiers": [
              { "Target": "swordsmanAttack", "Type": "Percent", "Value": 0.1 }
            ]
          },
          "advanced_armor": {
            "Id": "advanced_armor",
            "Prerequisites": ["melee_weapons"],
            "Cost": 100,
            "Duration": 40,
            "Modifiers": [
              { "Target": "swordsmanHP", "Type": "Absolute", "Value": 20 }
            ]
          },
          "siege_tech": {
            "Id": "siege_tech",
            "Prerequisites": ["melee_weapons"],
            "Cost": 150,
            "Duration": 60,
            "Modifiers": [
              { "Target": "Attack", "Type": "Absolute", "Value": 5 }
            ]
          }
        }
      },
      "science": {
        "Techs": {
          "counting": {
            "Id": "counting",
            "Prerequisites": [],
            "Cost": 0,
            "Duration": 0,
            "Modifiers": []
          },
          "writing": {
            "Id": "writing",
            "Prerequisites": [],
            "Cost": 30,
            "Duration": 15,
            "Modifiers": []
          },
          "mathematics": {
            "Id": "mathematics",
            "Prerequisites": ["writing"],
            "Cost": 80,
            "Duration": 30,
            "Modifiers": [
              { "Target": "IdeaGrowth", "Type": "Percent", "Value": 0.3 }
            ]
          }
        }
      },
      "physics": {
        "Techs": {
          "simple_machine_intuition": {
            "Id": "simple_machine_intuition",
            "Prerequisites": ["science:counting"],
            "Cost": 2000,
            "Duration": 30,
            "Modifiers": []
          }
        }
      }
    }
  }
  ```

  [注意事项]
  - Prerequisites 为空列表 [] 表示无前置，为根节点
  - 跨树前置写 "树Id:节点Id"（如 "science:counting"）：物理/化学树的根节点都依赖数学树（v0.3 / WP-2.1）
  - 前置的树 Id 或节点 Id 不存在、或前置关系成环（含跨树成环）→ 判 error，启动即报错
  - Cost 消耗的资源固定为 "Idea"
  - Modifiers 中的 Target 会传给 ModifierManager，可与建筑/事件的效果叠加
  - 研发完成后 sourceId=节点ID，方便以后撤销

================================================================================
  六、事件配置 (Events)
================================================================================

  文件名建议: Config/Events.json
  根元素: { "Events": [ ... ] }

  [字段说明]

  字段名                 类型                    必填  说明
  ────────────────────  ──────────────────────  ────  ───────────────────────
  EventId               string                   是    事件唯一标识
  Name                  string                   是    事件名称
  Description           string                   否    事件描述文本
  TriggerChancePerDay   float                    是    触发概率(0~1), **每游戏日**判定一次
                                                      0.001=0.1%概率/天；设计稿的事件表即按 %/日 填写
                                                      （如 0.05%/日 = 0.0005）
                                                      ⚠️ v0.3 / WP-2.8 起字段名由 TriggerChance 改为
                                                      TriggerChancePerDay：旧表不改名会静默变成 0
                                                      （事件永不触发），启动期校验会给出提示
  Duration              int                      是    效果持续天数, 0=永久
  Modifiers             [Modifier]              否    触发时注册的效果列表
  ResourcePrerequisites { string: float }        否    触发所需资源(不消耗则不写)
  TechPrerequisites     { string: [string] }     否    触发所需科技前提

  [完整样板 JSON]
  ```json
  {
    "Events": [
      {
        "EventId": "gold_rush",
        "Name": "淘金热",
        "Description": "金矿发现！金币产量短期飙升",
        "TriggerChancePerDay": 0.002,
  ```

  - 事件 Modifiers 的 sourceId 是 EventId，撤销时按 EventId 删除

================================================================================
  附录C、配置表校验（v0.3 / WP-1.4 起，启动期自动执行）
================================================================================

  7 张表（Config/{表名}.json）：Terrains / Resources / Buildings / Units / TechTrees / Events / Generator
  装载（能不能解析）与内容校验（对不对）都在 CoreBootstrap 装配时执行，结论：
    - 打到 Godot 控制台（ServiceContainer._Ready）
    - 随 CoreServices.ConfigReport 暴露给表现层与无头检查

  [分级]
  error   → 阻断启动；异常消息内含逐条问题清单（[ERROR] 表/Id: 说明）
  warning → 只提示，不阻断

  [error 清单]
  - 表文件缺失 / JSON 解析失败 / 根对象形状与 DTO 不符（如 Events 写成裸数组）
  - 表为空（每张表至少 1 条）
  - Id 为空、Id 重复、字典 key 与条目 Id 不一致
  - Terrains：Weight<=0、MoveCost<0
  - Resources：GrowInterval<0、BaseGrowth<0、BaseLimit<=0、BaseValue<0 或 > BaseLimit
  - Buildings/Units：Duration<0、ResourceCost 负值、HP<=0，以及攻击/移动/视野/人口相关字段为负
  - TechTrees：Cost<0、Duration<0、前置指向自己、前置成环（含跨树成环）、
               前置不在同一棵树内、跨树前置的树 Id 不存在、跨树前置的节点 Id 在目标树中不存在
               （v0.3 / WP-2.1：后两条本为 warning，收敛跨树前置后升级为 error ，
                因为填错即等于"该科技永久不可解锁"，见 TECH-07）
  - Events：TriggerChancePerDay 不在 [0,1]、Duration<0
  - Modifier：Type 不是 "Percent" / "Absolute"（其余拼写会被静默当成 Absolute，见 MOD-05）
  - 跨表：TechRequirements / TechPrerequisites 引用了不存在的科技树
  - Generator：Density<=0
  （时长字段的单位是「日」，因此 Duration/GrowInterval 只判"不能为负"；
    "单位写错"由下面的自检按 warning 处理）

  [warning 清单]
  - 未知地形 Id、未知资源名
  - 建筑/单位/事件表的 TechRequirements 引用了树内不存在的科技节点
    （v0.3 / WP-2.1：**科技树自身的 Prerequisites 已升级为 error**；这两者的差别是
      "别的表引用科技树"仍先降级，"科技树内部的前置闭合"必须强校验）
  - Modifier.Target 不在登记表内
    （登记表 = 固定名 ∪ 资源派生 {资源名}Growth ∪ 单位派生 {单位ID}Attack / {单位ID}HP）
  - Modifier.Value=0、Name 为空、TerrainRequirements 为空、ResourceCost 为空（免费）
  - Duration=0（瞬间完成）、MoveRechargePerTick=0、PopulationCost=0
  - 住房字段与 IsHousing 不一致（IsHousing=true 但 Cap/Radius<=0；非住房却填了人口字段）
  - Terrains 的 Weight 总和不等于 1；Generator.Density>50

  [单位自检（v0.3 / WP-1.5）]
  口径：所有时长字段的单位是**游戏日**（30 日 = 1 月、360 日 = 1 年）。
  规则：任何时长字段 > 360 即判 warning「疑似仍是秒口径」，
        涉及字段：Resources.GrowInterval、Buildings.Duration、
                  Buildings.PopulationGrowthInterval、Units.Duration、
                  TechTrees.*.Duration、Events[].Duration。
  为什么是 warning：口径错误不会让 JSON 解析失败，只会让节奏慢 N 倍且不易察觉，
        故提示但不阻断原型启动（分级原则见 D12）。
  为什么上界是 360：设计稿给的上限都在 1 年以内
        （建造 30~300、研究 0~180、事件 5~30、人口 180~300、经济 30）。
  常量定义处：Scripts/Core/Time/TimeConstants.cs（MaxPlausibleDays / 各节拍）
